# Coding conventions

## Comments

Write as few as possible. The default is none.

- Comment only what the code cannot say and is unlikely to change: a constraint, an invariant, a behaviour a reader would not expect.
- Do not restate what the code does. Detail goes stale, and a stale comment is worse than none.
- Do not point at anything that may be deleted — tickets, specs, other docs. A dangling reference is as bad as a stale one.
